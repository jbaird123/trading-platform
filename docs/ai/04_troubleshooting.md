# AI Module: Troubleshooting Guide

This document provides guidance for troubleshooting common issues encountered when working with the AI module.

## 1. Model Serving API Issues

### 1.1. `401 Unauthorized` Error

*   **Symptom:** API requests return a `401 Unauthorized` status code.
*   **Possible Causes:**
    *   Missing `X-API-Key` header in the request.
    *   Invalid or incorrect API key provided.
*   **Resolution:**
    1.  Ensure the `X-API-Key` header is present in your request.
    2.  Verify that the API key provided matches the `API_KEY` configured in `src/trading_platform/ai/serving/app.py` (or loaded securely in a production environment).

### 1.2. `500 Internal Server Error` during Prediction

*   **Symptom:** The `/v1/predict` endpoint returns a `500 Internal Server Error`.
*   **Possible Causes:**
    *   Errors during feature preprocessing.
    *   Issues with the loaded ONNX model (e.g., model corruption, incorrect input shape).
    *   Runtime errors within the prediction logic.
*   **Resolution:**
    1.  Check the server logs (where `uvicorn` is running) for detailed stack traces and error messages. The `logger.exception` in `app.py` will provide insights.
    2.  Verify the format and values of the input `features` in your request payload. Ensure they match the expected `PredictionRequest` schema.
    3.  If using a real ONNX model, ensure it is correctly loaded and compatible with the `onnxruntime` version.

### 1.3. API Not Responding / Connection Refused

*   **Symptom:** Cannot connect to the API endpoint (e.g., `curl: (7) Failed to connect to localhost port 8000: Connection refused`).
*   **Possible Causes:**
    *   The FastAPI server is not running.
    *   The server is running on a different host or port than expected.
    *   Firewall blocking the connection.
*   **Resolution:**
    1.  Ensure the `uvicorn` server is running. Check the terminal where you started it.
    2.  Verify the host and port. By default, it runs on `http://localhost:8000`.
    3.  Check your firewall settings to ensure the port is open.

## 2. Model Training Issues

### 2.1. Training Pipeline Failure

*   **Symptom:** The `AITrainingPipeline` fails during execution.
*   **Possible Causes:**
    *   Data loading errors (e.g., `DataNotFound`, schema mismatch).
    *   Feature engineering errors (e.g., NaN values, incorrect transformations).
    *   Model convergence issues or invalid hyperparameters.
    *   MLflow tracking errors.
*   **Resolution:**
    1.  Review the logs generated by the training pipeline for specific error messages.
    2.  Verify the integrity and format of your input data and feature sets.
    3.  Check the `AITrainingPipeline` configuration for correct hyperparameters.
    4.  Ensure MLflow is correctly configured and accessible.

### 2.2. Poor Model Performance

*   **Symptom:** Trained models exhibit low accuracy, poor financial metrics, or unexpected behavior.
*   **Possible Causes:**
    *   Data quality issues (noise, errors, insufficient data).
    *   Incorrect feature engineering or feature leakage.
    *   Suboptimal model architecture or hyperparameters.
    *   Concept drift or data drift (model trained on outdated patterns).
    *   Incorrect evaluation methodology.
*   **Resolution:**
    1.  Perform thorough data quality checks and visualize data distributions.
    2.  Re-evaluate feature engineering pipelines for potential issues.
    3.  Conduct hyperparameter tuning and experiment with different model architectures.
    4.  Utilize the `AIEvaluationProcedure` for time-series cross-validation and statistical significance testing.
    5.  Check for data drift and concept drift using monitoring tools.

## 3. MLflow Tracking Issues

### 3.1. MLflow UI Not Accessible

*   **Symptom:** Cannot access the MLflow UI after running `mlflow ui`.
*   **Possible Causes:**
    *   MLflow server not started or crashed.
    *   Port conflict.
*   **Resolution:**
    1.  Ensure `mlflow ui` command is running in your terminal.
    2.  Check if another process is using port `5000` (default MLflow UI port). You can specify a different port with `mlflow ui --port <new_port>`.

### 3.2. Missing Runs/Artifacts in MLflow

*   **Symptom:** Training runs or artifacts are not appearing in the MLflow UI.
*   **Possible Causes:**
    *   Incorrect `MLFLOW_TRACKING_URI` environment variable.
    *   Errors during `mlflow.log_param`, `mlflow.log_metric`, or `mlflow.log_artifact` calls.
*   **Resolution:**
    1.  Verify that `MLFLOW_TRACKING_URI` is correctly set to your MLflow tracking server or local directory.
    2.  Review the training pipeline logs for any errors related to MLflow logging.

## 4. General AI Module Issues

### 4.1. Dependency Conflicts

*   **Symptom:** `poetry install` or `poetry run` commands fail due to dependency resolution issues.
*   **Possible Causes:**
    *   Conflicting package versions in `pyproject.toml` or `poetry.lock`.
    *   Incompatible Python version.
*   **Resolution:**
    1.  Run `poetry update` to try and resolve dependencies.
    2.  If conflicts persist, manually inspect `pyproject.toml` for conflicting packages and try to adjust versions.
    3.  Ensure your Python environment matches the project's specified Python version.

### 4.2. Performance Bottlenecks

*   **Symptom:** AI module components (training, inference) are running slowly.
*   **Possible Causes:**
    *   Inefficient data loading or preprocessing.
    *   Suboptimal model inference (e.g., not using ONNX Runtime).
    *   Lack of hardware acceleration (GPU).
    *   Inefficient code or algorithms.
*   **Resolution:**
    1.  Profile your code to identify bottlenecks.
    2.  Optimize data loading and feature engineering steps.
    3.  Ensure ONNX Runtime is correctly utilized for inference.
    4.  Consider using a GPU if your model and infrastructure support it.
    5.  Review and refactor computationally intensive parts of the code.
