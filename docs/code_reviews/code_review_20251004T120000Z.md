refactor(portfolio): Clarify PnL calculation with movement and costs

This commit refactors the PnL calculation and reporting to provide a
clear, auditable waterfall from ideal price movement to net profit/loss.

The `pnl_gross` field has been replaced with `pnl_movement`, which
represents the pure mid-to-mid price change, excluding all transaction
costs. The final `pnl` is now explicitly calculated as `pnl_movement`
minus the sum of all costs (spread, commission, slippage).

This change provides a more realistic and transparent view of trading
performance.

- Replaced `pnl_gross` with `pnl_movement` in `Trade` dataclass.
- Added `entry_mid_price` to `Position` to track mid-price at entry.
- Updated `PortfolioManager` to calculate PnL based on the new waterfall.
- Updated `brief.json` schema and all reporting to reflect the change.
- Added a new test suite to verify the PnL calculation waterfall.
- Updated all relevant existing tests to align with the new structure.
